# 원 요청문 (2026-09-24, 사용자 작성 — 수정 금지)

이 저장소의 모든 기능·검수 기준은 아래 요청을 근거로 한다. AGENTS.md 3장은 이 요청을 규칙으로 옮긴 것이다.

```text
[https://youtube.com/@joshuamagazine?si=o2LN6zu1X9uYHl5W]를 레퍼런스로, 새로운 소재를 찾아 같은 편집 구조의 영상을 제작하는 실행 가능한 프리셋을 만들어라.

위 채널의 영상들중 조회수 80만 이상의 영상들을 전부 분석해라.

  목표는 분석 보고서가 아니라,
  “새 소재 탐색 → 선별 → 대본·컷 구성 → 편집 → 출력 검수”까지
  재사용할 수 있는 제작 시스템이다.

  1. 기준과 작업 순서
  - 분석 시점의 최신 100편을 기준으로 고정하고 목록·게시일을 저장한다.
    전체 영상은 참고이며 충돌하면 최신 100편이 우선한다.
  - 먼저 포맷을 표로 분류한다. 도입 방식만 다른 것과 전개 구조가
    실제로 다른 것을 구분하고, 포맷별 대표 영상을 지정한다.
  - 기존 조사·원본·측정값이 있으면 확인하고 재사용한다.
  - 접근·측정하지 못한 항목을 추측으로 채우거나 완료라고 하지 마라.
    미확정 항목이 제작에 미치는 영향과 해결 상태를 기록한다.

  2. 그대로 재현할 것과 바꿀 것
  - 재현: 화면 비율, 구도, 여백, 제목·설명·본문의 위치와 크기,
    글꼴·굵기·외곽선·박스, 등장·퇴장 모션, 컷의 전개 구조,
    확대·정지·전환, 자막의 말투와 등장 타이밍,
    BGM의 버전·사용 구간·크기, 원음 처리, 효과음의 종류·자리·빈도.
  - 변경: 소재는 반드시 다른 촬영본으로 교체한다.
    채널명·로고 등 원 채널의 고유 식별 요소는 복제하지 않는다.
  - 내가 별도로 지정한 변경
  - 요청한 변경과 미재현 결함을 검수표에서 구분한다.
  - 다른 프로젝트의 프리셋을 이 채널에 임의로 섞지 마라.

  3. 분석을 실제 제작 설정으로 연결
  - 수치 항목은 전체 및 포맷별 p10/p50/p90과 표본 수를 기록한다.
  - 화면·글자 좌표는 해상도와 함께 저장한다.
  - 글꼴은 비교 방법의 IoU 상한을 먼저 제시하고 후보를 검증한다.
    비슷한 글꼴과 동일성이 확인된 글꼴을 구분한다.
  - 모션·전환·BGM·원음은 있다/없다/못 잼으로 기록한다.
  - 각 설정에 “근거 영상·시각 → 측정값 → 제작 코드의 설정 →
    출력에서 확인할 검사”를 연결한다.
  - 보고서에만 적고 제작 코드에는 반영하지 않는 항목이 없게 한다.
  - 고정할 스타일과 새 소재마다 다시 판단할 좌표·시각을 분리한다.

  4. 자막과 편집 구조
  - 장면을 실제로 보고 들은 뒤 대본과 자막을 작성한다.
  - 한국인이 자연스럽게 받아들이는 짧고 센스 있는 표현을 쓰되,
    영상에 없는 관계·동기·대사를 지어내지 마라.
  - 제목, 상황 설명, 인물 식별, 실제 대사, 반응·효과자막을 구분한다.
  - 반전을 미리 설명하지 말고 레퍼런스의 정보 공개 순서를 따른다.
  - 얼굴·손·핵심 물체를 가리지 않는다.
  - 의미가 끝난 불필요한 꼬리는 제거하되 중요한 동작은 자르지 않는다.
  - 같은 효과를 연속으로 쌓거나 분량을 채우려고 반복하지 않는다.

  5. BGM과 원본 소리
  - BGM은 곡명뿐 아니라 버전·속도·실제 사용 구간까지 확인한다.
    같은 곡의 다른 부분을 넣으면 일치로 보지 않는다.
  - 깨끗한 음악 파일을 사용한다. 레퍼런스에서 분리한 음원을
    그대로 제작용 BGM으로 쓰지 마라.
  - 원본 소리는 기본 OFF.
    중요한 대사나 인물이 말하는 구간만 선별해 살린다.
  - 원본에 이미 붙은 음악은 우리 BGM과 겹치지 않게 제거한다.
    음성과 음악이 섞였으면 분리 후 음질을 검사한다.
  - 보존한 대사가 BGM에 묻히면 레퍼런스의 믹스를 참고해 덕킹한다.
    원음을 끈 구간에 불필요한 덕킹을 남기지 않는다.
  - 효과음이나 컷 자체를 덕킹의 이유로 삼지 않는다.
  - 직접 듣지 못했다면 청취 검수 완료라고 하지 마라.

  6. 효과음 카탈로그
  - 최신 50편을 Demucs로 분리하고 원래 믹스와 대조해,
    말·BGM 밑에 깔린 효과음까지 추출한다.
  - 소리 지문으로 종류를 묶고 편집 효과음과 원래 현장음을 구분한다.
  - 종류마다 다음을 기록한다:
    종류 / 편당 개수 p10·p50·p90 / 직전 자막 종류 /
    화면 사건 / 감정 / 자리 규칙 / 표본 3편의 시각.
  - 의도적 정적도 확인되면 별도 종류로 넣는다.
  - 제공한 효과음 창고에서 같은 계열을 찾아 sfx_map에 연결한다.
    없으면 없음, 미확인이면 못 잼으로 구분하고 필요한 자산을 확보한다.
  - 새 영상은 사건을 확인한 뒤 감정 태그를 붙이고,
    카탈로그 규칙에 맞는 소리를 배치한다.
  - 효과음은 컷 때문이 아니라 사건 때문에 들어가야 한다.
    편당 개수와 종류 분포는 해당 포맷의 관측 범위에 맞춘다.
    사건 없는 추가 효과음은 0개, 사건과 배치는 ±0.3초 이내다.

  7. 새 소재를 찾는 창고
  - 레퍼런스의 설명란·대본·화면 출처·캡처 검색·Google Lens로
    원본과 반복적으로 쓰이는 소재 계정·키워드를 역추적해 저장한다.
  - 레퍼런스가 사용한 촬영본은 제외 목록으로 관리한다.
    같은 키워드라도 새로운 촬영본을 찾아 제작한다.
  - YouTube/TikTok/Instagram/Reddit에서 검색한다.
  - 플랫폼별 관련 후보를 확인된 조회수 순으로 정리하고,
    최근성·사건의 강도·반전·화질·포맷 적합성으로 최종 선별한다.
  - 조회수 확인일을 기록한다. 좋아요를 조회수로 바꾸지 말고,
    과거 바이럴을 최신 영상이라고 하지 마라.
  - 원작자·재게시자·게시 URL·다운로드 경로·파일 해시·선정 이유를 남긴다.
  - 특정 플랫폼 접근이 안 되면 성공한 척하지 말고,
    가능한 다른 경로로 소재 확보를 계속한다.

  8. 원본 로고와 자막
  - 원본 영상에 붙은 고유 로고·출처 오버레이·원어 자막이
    최종 화면에 남지 않게 한다. 특히 상단 좌우와 내부 컷을 검사한다.
  - 깨끗한 원본 확보, 적절한 크롭, 국소 복원 순으로 처리한다.
  - 로고를 없애려고 중요한 인물이나 동작을 잘라내지 마라.
  - 화면에서 제거해도 원본 출처 기록은 별도 자료에 보존한다.

  9. 첫 편과 후속 제작
  - 첫 편만 소재·구간 시트·표지 문구·제목 후보 3종·효과음 배치표를
    구체적으로 제시하고 승인 뒤 렌더한다.
  - 이미 승인한 기획이나 수정 작업은 다시 승인받지 않는다.
  - 첫 편에서 확인된 수정은 프리셋과 후속편에 함께 반영한다.
  - 이후에는 지정한 포맷과 편수까지 불필요한 질문 없이 완료한다.

  10. 출력 검수와 완료 기준
  - 최종 MP4를 기준으로 검수한다.
    타임라인이나 코드가 맞다는 이유만으로 출력도 맞다고 하지 마라.
  - 레퍼런스 1편과 우리 편을 같은 절대 시각의 1초 격자로 비교한다.
    자막 띠 아래에 0.5초 간격 효과음 띠를 나란히 붙인다.
  - 검수표는 같다/다르다/못 잼으로 작성한다.
    의도한 변경은 따로 표시한다.
  - 글자 위치·폰트·자막 타이밍·컷·모션·음악 구간·원음·로고 잔류,
    효과음 종류별 개수·사건과의 시차·사건 없는 효과음 0을 검사한다.
  - 움직이는 장식은 실제 출력에서 위치와 밝기 변화를 각각 검사한다.
  - 요청하지 않은 차이는 고친 뒤 다시 검사한다.
    못 잰 항목은 완료로 승격하지 않는다.
  - 결함마다 고침·동일 사례 재검사·최종 관문 결과를 함께 남긴다.
  - 컨텍스트가 차기 전에 진행 기록과 재개 지점을 저장하고 커밋한다.

  11. 다른 컴퓨터에서 쓰는 실행 가능한 프리셋
  - 설명만 있는 MD가 아니라, 재사용할 설정·코드·자산·출처·예제 계획을
    갖춘 프리셋을 제공한다.
  - Claude Code와 Codex가 읽을 수 있는 공통 MD를 만든다.
  - 이전 컴퓨터의 절대 경로·사용자 이름·설치 환경에 의존하지 않는다.
  - 단일 MD를 요구하면 필요한 작은 실행 자산을 내장하고,
    에이전트가 긴 바이너리 본문을 읽지 않고 복원하는 방법을 넣는다.
  - 필수 프로그램·의존성의 확인과 초기 설정 절차를 포함한다.
    로그인이나 프로그램 설치가 저절로 끝난다고 주장하지 않는다.
  - 깨끗한 별도 폴더에 프리셋을 복원하고,
    다른 테스트 소스로 MP4와 편집 프로젝트를 실제 생성해 검증한다.
  - 검증한 OS와 검증하지 않은 환경을 구분한다.
  - 납품: 영상, 편집 가능한 프로젝트, 실행 프리셋,
    소재 창고, 비교 시트, 검수 결과.
    합성되어 개별 수정할 수 없는 부분은 정확히 설명한다.
```
